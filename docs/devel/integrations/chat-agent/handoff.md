# AI-Nexus Chat Agent：开发会话交接说明

## 任务背景

我们计划把 AI-Nexus 当前内置的对话能力拆分为独立 Chat Agent。

当前系统已经具备模型凭证管理、对话与消息管理、预设、流式模型回复、历史上下文、
用量记录和自动标题等基础能力。随着后续加入工具调用、记忆、知识检索和更完整的 Agent
流程，希望对话系统可以独立演进，并与 AI-Nexus 的用户、邮件、图片生成等核心功能隔离。

## 本次希望完成的事情

请先阅读同目录的 [需求说明](requirements.md)，然后：

1. 调研 AI-Nexus 当前对话模块，梳理已有能力和实际问题；
2. 根据需求提出独立 Chat Agent 的整体方案；
3. 说明 AI-Nexus 与新服务各自保留哪些职责；
4. 设计两个系统之间的调用方式和数据边界；
5. 设计对话执行、流式返回、取消、失败和重复请求的处理方式；
6. 规划现有模型凭证、对话、消息和预设的数据迁移；
7. 给出分阶段开发、测试、联调、切换和回退计划；
8. 方案确认后，再形成正式协议和开发任务。

## 需要重点解决的问题

- 用户只能操作属于自己的凭证、对话、消息和预设；
- 删除对话前必须确认资源归属，不能误删其他用户消息；
- 模型密钥必须安全保存和使用，不能通过日志或响应泄露；
- 自定义模型服务地址不能访问系统内网和敏感地址；
- 同一请求不能重复调用模型或重复保存消息；
- 同一对话的并发生成不能造成历史与消息顺序错乱；
- 流式执行必须明确区分完成、失败和取消；
- 部分输出不能伪装成完整回答；
- 客户端断开后，应停止不再需要的模型调用；
- 自动标题等后台任务不能影响主对话，也不能在重启后失去状态；
- Chat Agent 故障只能影响对话功能，不能拖垮 AI-Nexus 其他业务；
- 旧数据迁移期间不能形成长期双写和两套事实来源。

## 第一阶段范围

第一阶段以迁移和稳定现有对话能力为主，不要求一次完成多 Agent、长期记忆、知识库、
MCP、完整工具平台或图片生成工具。

## 对方案的要求

- 不要直接照搬当前 AI-Nexus 的内部代码结构；
- 不要因为旧文档曾经出现某种协议或技术方案就默认沿用；
- 技术栈、通信方式、数据存储和部署方案需要经过调研后提出理由；
- 优先保证职责清晰、数据安全、执行可靠、容易联调和可以逐步迁移；
- 对尚未确认的内容明确列为待决策项，不要假装已经形成协议。

最终希望先得到一份可讨论的需求分析和总体方案，双方确认后再开始编码。
