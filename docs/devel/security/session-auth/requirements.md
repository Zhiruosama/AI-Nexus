# 可撤销会话认证：需求目标

## 1. 背景

当前系统使用 JWT 进行 HTTP 鉴权。登录成功后会把 Token 写入 Redis，退出登录时删除 Redis 中的记录，但 HTTP 鉴权中间件只验证 JWT 签名和过期时间，没有检查 Redis 会话状态。

因此，用户退出登录后，旧 JWT 在自身过期前仍可能继续访问受保护接口。

## 2. 目标

建立“JWT 身份证明 + Redis 会话状态”的双重认证机制：

```text
JWT 有效
+ Redis 会话存在
+ JWT 用户与 Redis 用户一致
→ 请求认证成功
```

用户退出登录、主动踢出会话或服务端撤销会话后，对应旧 Token 必须立即失效。

## 3. 功能需求

### 3.1 登录创建会话

- 登录成功时生成不可预测的会话 ID `session_id`。
- JWT 使用标准 `sub` 表示用户 ID，使用 `jti` 表示会话 ID。
- Redis 创建对应会话记录，并设置不超过 JWT `exp` 的 TTL。
- 同一用户可以拥有多个并行会话。

### 3.2 请求认证

受保护接口必须依次完成：

1. 读取并解析 Bearer Token；
2. 校验 JWT 签名算法和签名；
3. 校验 `exp` 等标准声明；
4. 读取 `sub` 和 `jti`；
5. 查询 Redis 会话；
6. 校验 Redis 中的用户 ID 与 JWT `sub` 一致；
7. 将认证后的用户主体写入请求上下文。

任一步骤失败，都必须终止请求链，不得继续执行后续 Handler。

### 3.3 退出登录

- 从当前认证主体取得 `jti`。
- 删除对应 Redis 会话记录。
- 删除后，原 JWT 即使未到 `exp`，也不能继续访问受保护接口。

### 3.4 会话撤销扩展

- 当前退出登录只撤销当前 `jti` 对应的会话。
- 密码重置和账号注销必须撤销该用户的全部会话。
- 设计应支持未来由管理员踢出指定会话，不要求本阶段实现管理界面。

## 4. 非目标

- 本阶段不引入 OAuth/OIDC 或第三方身份提供商。
- 本阶段不实现刷新 Token 和设备管理 UI。
- 本阶段不将角色权限直接塞入 JWT；角色授权另由 RBAC 需求设计负责。
- 本阶段不改变业务资源 owner 校验，任务 owner 属于后续独立任务。

## 5. 安全要求

- `jti` 必须使用密码学安全随机值，不能使用可预测的自增 ID。
- JWT 不得保存密码、API Key 或其他敏感明文。
- Redis 会话 TTL 必须与 JWT 有效期一致或更短。
- JWT 中的 `sub` 与 Redis 会话中的用户 ID 不一致时必须拒绝。
- 认证失败统一返回未授权结果，不泄露“用户存在/会话存在”等内部细节。

## 6. 验收标准

- 正常登录得到的 JWT 可以访问受保护接口。
- 修改 JWT 内容或签名后请求被拒绝。
- JWT 过期后请求被拒绝。
- 删除 Redis 会话后，原 JWT 立即失效。
- Redis 用户 ID 与 JWT `sub` 不一致时请求被拒绝。
- 认证失败时后续业务 Handler 不会被执行。
- 密码重置或账号注销后，该用户的全部旧会话失效。
- 现有登录、退出登录和 Postman 鉴权流程不回归。
